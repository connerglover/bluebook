1. Load the test

Pick the .bbtest you are keying. It is read in this page only — nothing is uploaded, and the plaintext answers never leave your browser.

2. Enter the answers

Only the types with a fixed set of choices can be scored, so only those are listed. Use letters: B for multiple choice, A,C for select-all, 1-A, 2-C for matching. Leave a row blank to skip that question — it will not count toward the score.

3. Take the hashed key

This replaces (or becomes) the "key" block in your .bbtest. You can also let the page write the whole file for you.

Detailed lets a student learn the key by elimination on a retake. Use it for a one-off review, not for a test you plan to reuse.

What the hashing does and does not do

Each answer is stored as SHA-256(salt : questionId : answer). A student who opens the file, or the devtools console, sees hashes rather than letters.

This is obfuscation, not security. The salt has to ship with the file so the browser can verify against it, and with five choices per question anyone willing to write a five-iteration loop recovers the whole key. It defeats a casual look and nothing more. If a key genuinely must stay secret, it cannot be in the browser at all.
